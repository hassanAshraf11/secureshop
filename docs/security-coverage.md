# Starter Security Coverage Matrix

The paths below are relative to the project root. “Passed” records a specific automated or manual check. The team's formal Red Team exercise remains pending.

| Topic | Feature and root cause | Defense | Code location | Evidence and status |
| --- | --- | --- | --- | --- |
| Lab 1 · client-side trust | A submitted total or account ID could change who pays or how much | Use the session identity and calculate integer-piastre totals from database rows | `app/Services/Checkout.php`, `CartController.php` | Passed · `PurchaseTest::test_keyboard_purchase_replay_receipt_refresh_and_owner`, `test_cart_is_scoped_and_cart_updates_persist` |
| Lab 2 · business rules | Repeated subscriptions or switching discounts could duplicate value | Unique normalized recipient, recipient check, expiry, one selected coupon, global counter and unique per-account redemption | `StoreController::newsletter`, `Checkout::quote`, shop migration | Passed · `CatalogueTest::test_newsletter_resends_one_coupon_and_checks_recipient_and_cap` and `PurchaseTest::test_coupon_replacement_expiry_and_previous_redemption` |
| Lab 2 · exceptional inputs | Stale inventory, new prices or inadequate credit could produce a partial order | Validate quantities, compare the reviewed quote and roll back failed transactions | `CartController::change`, `Checkout::pay` | Passed · `PurchaseTest::test_stock_and_price_are_checked_again_at_payment` and `test_insufficient_credit_keeps_credit_stock_and_cart` |
| Lab 2 · workflow and concurrent payment | A repeated purchase or refresh could cause another charge | Per-user row lock, unique purchase key, post/redirect/get and read-only receipt | `Checkout::pay`, `CartController::receipt`, migration | Passed · acceptance replay and `ConcurrencyTest::test_two_database_connections_replay_one_purchase` on MySQL |
| Lab 3 · identity and MFA | Confusing email ownership with login, trusting a submitted account or replaying a valid code | Separate email confirmation, password-bound nonce, hashed six-digit email code, 60-second expiry, one-use consumption, throttled attempts and row lock | `AuthController.php`, `Addresses.php`, `AppServiceProvider.php` | Passed · registration/enrollment, missing/expired challenge, cooldown across sign-ins and replay tests in `IdentityTest.php` |
| Profile email change | A profile update could activate an unverified address | Same normalized email rules on both forms, pending address, hashed expiring confirmation token and final uniqueness constraint | `Addresses.php`, `AccountController::update`, `AuthController::verify` | Passed · `IdentityTest::test_changed_email_requires_ownership_and_profile_is_allowlisted` |
| Session lifecycle | A pre-login session could remain usable after authentication or sign-out | Regenerate identifiers, require a session-bound completed factor, invalidate on logout | `AuthController.php`, `ShopAccess.php` | Manual sign-in reached the authenticated account page; automated session lifecycle checks pending due to CSRF failures |
| Access control | A customer could select another customer's receipt/cart or an administrative route | Scope queries to the session user, enforce admin and active status on the server | `routes/web.php`, `ShopAccess.php`, `CartController.php` | Passed · guest protection, admin denial, deactivated session, cart isolation and receipt ownership tests |
| Mass assignment | Registration or profile fields could set a role or credit | Allowlisted fields, database defaults, explicit admin edits | `User.php`, `AuthController::register`, `AccountController::update` | Passed · role and balance assertions on both forms in `IdentityTest.php` |
| SQL and output handling | Untrusted filter values or product text could become query syntax or markup | Bound query-builder values, fixed sort mapping, escaped Blade interpolation | `StoreController::index`, `resources/views/` | Passed · sort allowlist, search and HTML escaping checks in `CatalogueTest.php` and `BrowserControlsTest.php`. Broader input review pending. |
| CSRF | A state-changing browser form could omit proof of session intent | Laravel web middleware and CSRF tokens on state-changing forms | `routes/web.php`, `resources/views/` | Passed · `BrowserControlsTest::test_browser_post_requires_csrf` with real CSRF middleware enabled |
| Historic receipts | Live joins would change an old receipt when products or prices change | Snapshot product name, unit price, quantity, applied coupon, totals and remaining balance | `Checkout::pay`, `store/receipt.blade.php` | Passed · price/name/deactivation followed by repeated receipt reads in `PurchaseTest.php` |
| Secret handling | Access URLs, logs or a cached enrollment page could retain secrets | Email token in a URL fragment, hashed token, hashed one-time code, no-store headers, generic exception reports and no SMTP log transport | `Addresses.php`, `BrowserHeaders.php`, `bootstrap/app.php`, `.env.example` | Configuration and code reviewed. Comprehensive log and browser-cache inspection pending. |
| Labs 4–5 · advanced admin login | Signals and device proofs need an agreed enrollment and recovery policy | Separate integration proposal for typing, real passkeys, location and login windows | `docs/admin-login-labs.md` | Pending instructor clarification. No simulated input is used for authentication. |
| Formal Red Team exercise | Independent assessment and evidence collection | Team-defined scope, findings and retest record | Team deliverable | Pending |
